## v0.2.1：本地 PDF 练习首版

AndroidPdfViewer 当前 Maven Central 的 dev.zwander:pdfviewer:5.0.0 AAR 实测 minCompileSdk=36，POM 含 Kotlin2.3.10/core-ktx1.18.0；不对墨灵 compile34 工程强行升级。按审计备选使用 Android 平台 PdfRenderer，通过 PdfEngine 隔离；不重写 PDF 解码器。

现有设置页增加 PDF 工作区入口。SAF 导入≤100MB 本地副本，以原始 PDF SHA256 为文档ID；单页渲染最长边1800像素，页面坐标按平台渲染页尺寸（point）定义。写字、拖动、±缩放、撤销、矩形选区、手动整页/局部批改与选区解释，均在独立原生 Activity 内，不改变自由手写流程。当前是矩形选择，尚无自由套索和压感笔宽表现；压力/时间保留在矢量数据中。

存储通过 PaperStore：original.pdf、每页 ink.json、提交源笔迹快照、结果JSON分开；AtomicFile 保存笔迹/结果。每次落笔结束排队保存，提交前存不可变源快照，结果带 documentId/page/sourceRevision/region/sourceVectors；继续写字不会改变已发出的图片或覆盖当前笔迹。结果从本页批改记录读取。模型请求只手动触发，订阅以外的文本 Provider 明确不接受图片。

仍待设备验证：PDF 渲染/触控/大文件/杀进程恢复；无圆形套索、逐笔橡皮擦、原PDF导出、Room迁移、Drive授权同步、Agent、跨设备冲突处理。截图只是模型输入派生物，不作为唯一保存格式。原文件损坏或笔迹尺寸不匹配时停止加载并保留原文件。

构建历史：v0.2.0首次CI因debug应用label与主清单冲突失败，未发布APK；v0.2.1显式声明label覆盖。

## 2026-10-29 v0.2.3：授权页面回归修复

用户反馈浏览器回调通过但软件未通过。代码检查发现：集成页将授权与紧随其后的模型列表绑定为一个操作，列表失败也显示整段失败；页面 onDestroy 在 busy 时会取消应用级授权并清除令牌。现有反馈不足以判定具体触发点，不标记实机根因已确认。

修复：LoginOperation 在应用级保留状态与任务，Activity 重建只重新观察；仅显式取消终止授权，不把 state/URL/令牌写入诊断或磁盘。仅前台页面消费一次浏览器启动链接。登录完成后由用户单独点击获取模型，列表失败不覆盖登录状态。恢复实时阶段和固定错误码。新增12项纯Java状态机检查，覆盖重复启动、界面重新附着、取消和旧任务晚到的结果隔离；仍需设备验证浏览器切换与系统回收行为。

## 2026-10-29 v0.2.4：接通主界面订阅视觉识别

用户截图显示原有 NO_RECOG_TIP，代码确认 runRound 在本机识别不可用时直接进入旧自建服务分支，从未到达 ModelProvider。这是此前只接通识别后文字回复所遗漏的路径；提示本身不能区分 GMS 缺失与下载/识别失败。

新增 HandwritingRecognition、InkVisionProtocol：本地成功则不请求图片模型；本地失败且用户已选订阅时发送当前笔迹 PNG，只请求 JSON 转写，不执行图中指令。转写结果进入原低笔画误触判断、空结果、/new、六轮历史、回答与保存流程。正常提问两次订阅调用，/new/低笔画拒绝后不发回答请求；本地识别优先，未切换到第三方计费通道。选择原 API 时沿用旧识别服务降级。没有改变授权协议和页面生命周期。

新增单测覆盖本地优先、视觉失败不再转其他通道、空结果、新会话命令、OCR 请求图片/无历史/JSON 提示及格式错误拒绝。构建通过不等于实机主界面识别完成；需用户验证所选模型图片能力、实际文字和最终回复。
