# WE v0.12 Preview — unified application surfaces

The workspace list is now the real home, with persistent Workspace / Settings / About navigation and direct canvas/conversation actions. The hidden historical reader remains an archive compatibility implementation, not an overlapping second home. System bars are visible and home orientation is unlocked.

All native surfaces share the paper palette, readable secondary text, 48dp minimum controls, selection/focus/ripple feedback, primary action hierarchy and labelled forms. Dialogs use the same palette. The MCP WebView has a native back header, matching CSS, wrapping status/actions, explicit hidden styles and 48px actions. Pairing protocol and subscription authentication/model operations are unchanged.

- Workspace management stays inline on home; explicit legacy modal entry points remain compatible. Search/sort/selection, archive/trash/restore and external index events use the existing workspace implementation.
- Settings navigation guards unsaved API/provider changes, with save/discard/cancel. Optional reader/legacy pen settings are collapsed.
- Conversation uses an app bar, workspace picker, expanding transcript and a single bottom composer/send-stop action. Draft input survives recreation, stopping a running task on return is explicit, and invalid workspace names/MCP JSON retain input.
- Subscription settings has consistent navigation, model control labels and collapsed diagnostics, preserving gateway/session/model state logic.
- Connection-page reconnect is single flight and releases controls on failure; unchanged status is not re-announced each polling cycle.

Validation: compilation, unit tests, lint, paired relay/WebView regression and the existing Android drawing/session contracts. New Android surface tests capture phone, landscape, tablet and reduced-height windows with actual system font scales 1.0 and 1.3; they restore system scale afterward. Screenshot review is required before publishing.

The deliverable is a separate `com.opc.moling.preview` application labelled WE 预览. It can coexist with earlier builds, protecting their local workspaces. Preview workspaces and login are independent; no automatic migration or in-place upgrade is claimed. CI preview signing remains ephemeral; persistent signing for subsequent preview upgrades still requires a separate release setup.
